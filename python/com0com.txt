Windoz/DOS limitation: comports can only connect to ONE application 

the DSC alarm panel 4 wire keypad bus is connected to a custom pic interface
which provides a connectiom to COM 4 2400 baud 8n1 on an XP box

This PIC interface provides the ability to simulate a RK3000 Keypad both keypad
and display elements ... it was originally connected to a VB6 Application which
has been updated to VB2K8 to run on XP and W7 

In 2024 I converted this VB2K8 to a HA custom Card which requires an MQTT Broker 
In order to interface this PIC interface to the HA virtual keypad I built a 
RK3K Serial to MQTT python bridge which uses python 2.7 to connect to the MQTT
broker running on the M73 Ubuntu box 10.213.69.17
  pc3000 send cos -> pic -> com 4 -> mqtt rk3k/cos -> mqtt broker
  mqtt broker -> ha virtual keypad
  pc3000 rcvs cmd <- pic <- com 4 <- mqtt rk3k/cmd <- mqtt broker    
  mqtt broker <- ha virtual keypad

But this python connection requires shutting down the VB2K8 app to link HA to
the PIC interface because they both can't connect to the same device on com4

HOWEVER it came to my attention that com0com and hub4com, could be used to share
this COM 4 port with both ports 

its not completely intuitive basically hub4com connects to 2 virtual comports
which are linked to com0com comport pairs and share data 

pic <-> com 4 <-> com 7 <-> com  8 <-> VB app
              <-> com 9 <-> com 10 <-> python mqtt bridge 

for XP we need to install com0com v2.22 x86
                     copy hub4com.exe to the com0com program folder
	      
setupc.exe install PortName=COM7 PortName=COM8 
setupc.exe install PortName=COM9 PortMame=COM10
